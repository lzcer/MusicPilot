# 1. PWA 的使用范围

MusicPilot 在生产构建中提供 PWA。使用 HTTPS 域名访问；本机 `localhost` 和 `127.0.0.1` 可用于验证。开发服务器不注册 Service Worker。

首次访问并完成后台缓存后，应用页面、脚本、样式和应用图标可直接从浏览器本地缓存读取。页面仍按路由懒加载执行。首次打开需要下载资源，PWA 不会加速服务端查询、站点搜索或下载任务。

## 1.1. 安装

支持安装提示的浏览器会在顶部显示“安装应用”。也可以使用浏览器菜单安装。iPhone/iPad 使用 Safari 的分享菜单选择“添加到主屏幕”。安装后的应用仍使用原来的域名和服务端会话。

## 1.2. 离线与登录

Service Worker 只缓存构建产物，不缓存 `/api/`、登录响应、SSE、音乐文件或外部封面，不排队重放写操作。打开应用仍向服务器验证会话。

网络断开时，已缓存的页面可以打开，并显示离线提示；音乐库查询、保存配置和下载操作需要联网。连接恢复后，启动期间失败的会话检查会自动重试。服务不可达但设备仍联网时，会显示连接失败及重试入口。

# 2. 版本更新

新版本在后台下载完毕后显示“新版本已准备好”。点击“稍后”可继续当前操作；保存编辑内容后，点击“刷新更新”应用新版。暂缓更新后，可通过顶部“有更新”重新打开提示。

应用在注册时、重新回到前台、网络恢复时及前台每小时检查更新，频繁切换窗口的检查会合并。首次缓存延后到页面加载后进行。Service Worker 激活时清理已过期的构建资源。

多个窗口共享同一域名的 Service Worker。在一个窗口应用更新后，其他窗口会显示刷新提示，不自动刷新其中正在编辑的内容。

# 3. 构建与 Cloudflare Tunnel

运行 `npm ci` 和 `npm run build`，部署完整的 `frontend/dist`。Docker 构建已包含这些步骤，不需要额外的 PWA 服务。构建环境需要 Node.js 20.19+ 或受支持的更新版本，现有 Docker Node 22 镜像满足要求。

| 资源 | 缓存要求 |
| --- | --- |
| `/sw.js` | `Cache-Control: no-store`，确保更新检查访问当前版本 |
| HTML、`/manifest.webmanifest`、稳定名称图标及 Workbox 脚本 | `Cache-Control: no-cache`，重新使用前校验 |
| `/assets/` 下带内容哈希的文件 | `public, max-age=31536000, immutable` |
| `/api/` | `Cache-Control: no-store`，不加入 Service Worker 缓存 |

后端已设置这些响应头，并为 manifest 返回 `application/manifest+json`。Cloudflare 自定义缓存规则应保留这些约定：不要用“缓存所有内容”覆盖 `/sw.js`、HTML 或 `/api/`；存在这类规则时，应为这些路径设置绕过缓存。已有边缘缓存的旧 HTML/Service Worker 需要在规则调整后清除。

发布后检查：正常登录；刷新不闪登录页；安装入口或浏览器安装菜单可用；暂时断网后页面仍可打开；部署下一版本后出现更新提示，并在确认后加载新版。实际 Tunnel 的耗时和缓存命中需要在部署域名上测量。
